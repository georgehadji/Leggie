## 3. Per-region process (condensed V7 Phases 2-8)

For each region, in order:

1. **Phase 2 (suspicion generation):** read every file in the region; generate candidate defects against the V7 taxonomy (boundary/arithmetic, resource lifecycle, concurrency, error/exception paths, trust boundary, type/serialization, state machine, contract/dependency), each naming the violated property and a reachability path from a real entry point (CLI command or public method the flow calls).
2. **Phase 3 (proof):** for each candidate ranked by `severity × prior × reachability`, write an executable trigger (real pytest test, not reasoning) and attempt the innocence defense (find the guard/invariant that clears it). No mocking away the mechanism under test.
3. **Phase 4 (triage):** classify VERIFIED DEFECT / FALSE (innocent, recorded) / UNKNOWN (needs runtime instrumentation, e.g. a live smoke — route to leggie-remediation-campaign instead of blocking this region).
4. **Phase 5 (fix):** classify layer + risk class per **leggie-change-control** §1 before writing the diff. ≤15 lines / ≤1 function per defect or escalate. Domain edits are refused by the guard hook — flag instead. Route-file/port edits get the hook's ask-first treatment, not a silent edit.
5. **Phase 6 (self-review):** the six RAR vectors, tagged VF/HYP/CANNOT DETERMINE.
6. **Phase 7 (tests):** proof-of-defect + ≥2 boundary + no-regression test, using this repo's real test style (see any `tests/unit/**/test_*.py` for convention — pytest, `pytest.mark.asyncio` where needed, fakes over mocks for port implementations per the existing `_CountingRerankerPort`-style pattern).
7. **Run offline gates** (`pytest -q` at least on the touched test file plus the full suite before moving on; `mypy leggie/`; `ruff check`; `lint-imports --debug --verbose`) before advancing to the next region — never carry a red region forward.
8. **Record** the region's findings in this file's §1 table (append, don't overwrite) with the next DH-N ids, and note in the commit message which region/DH-ids it closes, per **leggie-change-control** §4 commit conventions.

### 6.2 Every REQUIRES HUMAN REVIEW / CONSTRAINT-FORCED ESCALATION item, by ID

None of these 5 were fixed. Each needs a human-authored, dedicated plan doc
(or a judgment call this campaign was not chartered to make) before anyone
attempts a patch:

- **DH-9** (R2, parser) — `find_toc_span` only excises one pre-body
  heading-dense region; a bill with a second one (e.g. an explanatory
  memorandum walking through "Άρθρο 1, 2, 3..." before the real body)
  produces duplicate/phantom articles. Bounded today by the existing
  `is_clean` abort gate, not silently catastrophic — but the fix site is the
  exact F0 phantom-articles incident file, and a rushed patch risks
  reintroducing that regression.
- **DH-10** (R2, ingest) — `BoundedIngestor`'s `timeout_s` stops the caller
  waiting, not the underlying `asyncio.to_thread` work; repeated timeouts
  leak permanently-busy workers out of the process's shared default thread
  pool. The real fix is a different execution model
  (`ProcessPoolExecutor`-class), an architecture decision with real
  trade-offs, not a small patch.
- **DH-28** (R7, citation) — `LAW_REF_PATTERN` (Greek individual-law
  citations) has been dead code since the initial MVP commit; wiring it in
  naively was proven actively harmful, not merely incomplete — the packaged
  resolution index has zero law-ref identifiers, so any such citation would
  resolve `checked=True, resolved=False`, which `CoVeVerifier` already
  treats as positively disproven, silently hard-dropping findings that cite
  real, valid laws. Needs either a Domain `CitationScheme` addition
  (hook-blocked) plus a populated index, or reopening R4's already-closed
  CoVe scope.
- **DH-34** (R10, Domain) — `model_config = {"frozen": True}` blocks
  attribute reassignment but not in-place mutation of a `list`/`dict`-valued
  field, and `model_copy(update=...)`'s default shallow copy (used at every
  production call site) means an "old" and "new" version of the same
  `Finding` share the identical `evidence`/`counter_evidence` list object —
  narrowing leggie-architecture-contract's own Invariant #3 to an unenforced
  convention. System-wide blast radius across every mutable-collection field
  on every frozen Domain model; fix is a Domain model-shape change, hook-
  blocked, its own class-A change per non-negotiable #2.
- **DH-35** (R10, Domain) — `Event` is the only one of 16 frozen models with
  `use_enum_values: True`, so `event.event_type`'s runtime type is a bare
  `str` despite being annotated `EventType` — `isinstance(...,
  EventType)` is `False` and `.value` access raises `AttributeError`. Zero
  current exploitation found, but a real contract violation mypy cannot
  catch. Fix is a Domain model-config change, hook-blocked.

### 6.4 Residual risk — what this campaign did NOT cover or could not fully verify

Stated plainly, per non-negotiable #1 ("green tests ≠ working product") and
this doc's own house style — brutal honesty over a tidy-looking finish line:

1. **No live LLM smoke run was performed for any of the 24 FIXED, offline-
   verified-only defects**, by this campaign's own explicit, deliberate
   exclusion (paid runs against the $5/run cap are the separate, already-
   tracked 91-article yield campaign — **leggie-remediation-campaign**).
   Every class-A fix in §6.1 is proven by a targeted unit/integration test
   exercising the real mechanism at a mocked transport/port boundary, never
   by an actual end-to-end run against a real bill with a real LLM. Whether
   these 24 fixes, applied together, change the pipeline's live yield
   numbers (findings/article, parse-failure rate, skeptic/CoVe verdict
   distribution) in practice is **unmeasured**. The pre-existing gap this
   campaign started with — the 91-article full-bill run has never completed
   even once — is exactly as open now as before this campaign began; this
   campaign hunted defects, it did not attempt that run.
2. **DH-2 (test-order-dependent flake) remains OPEN**, root cause still not
   conclusively identified after three separate regions (Stage 0, R2, R4)
   each added evidence. At least two confirmed mechanisms
   (`configure_logging()`'s idempotent first-call-wins guard;
   `logging.disable()` left set by something outside `leggie/`/`tests/`)
   plus credible evidence of a third, never-pinned-down one. The two
   originally-named tests
   (`test_rerank.py::TestModelBasedRerankerDegradation::test_port_failure_is_logged`,
   `test_deliberative_prompts.py::TestPerspectiveFallback::test_unknown_perspective_logs_warning`)
   fired at least once in nearly every region's own final gate run,
   including R10's (this region's own closing run hit the `test_rerank.py`
   one), always re-confirmed passing in isolation immediately after. Net
   effect: any single `pytest tests/ -q` run of this suite has a real,
   nonzero chance of showing a red result unrelated to actual code health —
   this is a standing, unresolved threat to "green tests" as a fully
   trustworthy signal for this specific repo, not merely a cosmetic
   annoyance. Fixing it needs the exact reproduction recipe DH-2's own
   entry already lays out (capture a real `--randomly-seed=N`, replay,
   bisect) — nobody has done that yet.
3. **DH-9, DH-10, DH-28, DH-34, DH-35 remain unfixed** (§6.2) — each by
   design, not oversight: three cross a fenced architecture boundary (parser
   phantom-article risk, thread-pool execution model, citation/Domain
   scheme addition) and two are Domain-frozen for this entire campaign.
   Every one needs a dedicated plan doc and a human decision before a patch
   is safe.
4. **DH-21's alternate hypothesis was never separately ruled out.** DH-22
   (R6) statistically proved the concurrent-writer `os.replace()` collision
   mechanism (0/1850 failures post-fix, 52-73% pre-fix) and this fully
   explains the observed symptom — but DH-21's own original write-up also
   named a plausible Windows-AV/indexer-contention variant for the specific
   `test_resume_after_crash` flake (which uses a private `tmp_path`, so no
   second application writer was actually present there), and DH-22's own
   entry says plainly that this was not independently ruled out, only shown
   to be "the same underlying collision shape either way." Low residual
   risk (the fix defends against both variants regardless) but not a closed
   loop of proof for that one specific historical flake.
5. **The ≈47 cleared (FALSE/dead) candidates rest on one region's own
   investigation each**, not a second, adversarial re-review — except in the
   handful of cases a region's own brief explicitly asked for a
   re-verification of a PRIOR region's claim: R4 independently re-read and
   re-confirmed R3's claim that `bill_overview.py`'s
   `_generate_article_overview()` fully guards its own LLM call ("not trusted
   blindly," per R4's own write-up), and R6 independently re-confirmed R1's
   cleared `BudgetGuardDecorator` reserve/settle race-freedom claim under
   concurrent async callers. Those two are real second opinions; most other
   "cleared" verdicts (including R10's own ≈9) rest on that one region's own
   investigation alone. The V7 protocol this campaign followed treats
   "cross-check against the existing ledger before calling something new" as
   sufficient rigor for a clearance: that catches doc drift (DH-3's own
   founding example) but does not amount to an independent second opinion on
   every single clearance.
6. **R10 (Domain) found 2 new, previously-undocumented defects (DH-34,
   DH-35) that no later region existed to independently re-check**, since
   R10 is the last region in this campaign's sequence. A couple of earlier
   regions' findings got the kind of independent second look item 5
   describes (R3's by R4, R1's by R6); most did not, and DH-34/DH-35 are
   in that same more-common no-second-look position, not a uniquely worse
   one. Both come with an empirical proof script's output reproduced
   directly in this session (not merely reasoned about) and a locked-in
   characterization test each, which partially offsets the lack of a
   second reader, but a truly independent second read has not happened.
7. **This campaign's fixes were never re-run against the Phase 0 eval
   harness's gold-set precision/recall/F1/RDI numbers.** Whether 24 real
   defect fixes measurably changed (improved, regressed, or left unchanged)
   the actual finding-quality metrics the whole project is ultimately
   judged by is unmeasured — the same "green tests aren't the same as a
   working, GOOD product" lesson non-negotiable #1 encodes, now applied to
   this campaign's own output rather than to the original stub-MVP.

**Honest bottom line:** this campaign found and disposed of 28 real,
previously-unknown defects across 9 non-Domain regions with tests and green
gates at every step, correctly refused to patch 5 more that needed either a
dedicated plan doc or a frozen layer's sign-off, left 1 known test-flake
exactly as unresolved as it started (with substantially more diagnostic
evidence than before), and closed 1 defect's investigation via a later
region's independent proof. It did not — by explicit, deliberate design, not
oversight — touch the project's actual live yield numbers, which is the
harder and still-open question **leggie-remediation-campaign** exists to
answer next.
